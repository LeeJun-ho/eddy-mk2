# 커밋 컨벤션

`npm run commit` (commitizen + cz-customizable) 과 동일한 형식으로 커밋 메시지를 구성하여 `git commit -m`으로 실행한다.

```
<타입>(<스코프>): <설명>

<본문 - 선택>
```

**타입 목록**

| 타입       | 설명                      |
| ---------- | ------------------------- |
| `init`     | 처음 세팅                 |
| `feat`     | 새 기능 추가              |
| `fix`      | 버그 수정                 |
| `docs`     | 문서만 수정               |
| `style`    | UI/스타일·포맷만 변경     |
| `refactor` | 코드 구조·품질 개선       |
| `perf`     | 성능 개선                 |
| `test`     | 테스트 코드 추가/수정     |
| `chore`    | 의존성·설정 등 유지보수   |
| `build`    | 빌드·배포 파이프라인 변경 |

**스코프 목록:**

`batch`
(`chore` 타입은 추가로 `deps`, `config`, `other` 사용 가능)
(스코프 생략 가능 / 커스텀 스코프 허용)

**주의사항**

- 커밋 메시지에 `Co-Authored-By` 등 AI 서명을 추가하지 않는다.
- 변경 사항의 성격에 따라 여러 커밋으로 나눠도 되지만, 반드시 나눌 필요는 없다.
