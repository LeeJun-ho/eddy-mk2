## STEP 1 — 코드 리뷰

`git diff develop...HEAD`로 현재 브랜치의 변경사항을 확인하고, spec과 대조하며 요구사항 누락/초과 여부를 포함해 리뷰한다.

리뷰 기준은 아래 순서로 적용한다:
1. `.claude/code-review-guideline.md`가 있으면 → 해당 파일의 기준을 따른다.
2. 없으면 → 아래 관점에서 포괄적으로 리뷰한다.

   **요구사항**
   - spec 대비 구현 누락 여부
   - spec 범위를 초과한 불필요한 구현 여부

   **아키텍처 / 설계**
   - 레이어 역할 분리 준수 여부
   - 단일 책임 원칙(SRP) 위반 여부
   - 불필요한 의존성 추가 여부

   **버그 / 안전성**
   - null/undefined 처리 누락
   - 경계값 및 엣지 케이스 처리 여부
   - Race condition 가능성

   **보안**
   - 인증/인가 누락
   - 민감 데이터 노출 여부
   - 입력값 검증 누락

   **성능**
   - N+1 쿼리 등 불필요한 반복 호출
   - 불필요한 데이터 과다 조회

   **코드 품질**
   - 불필요한 중복 코드
   - 명확하지 않은 네이밍
   - 사용하지 않는 import/변수

## STEP 2 — 리뷰 결과 저장

리뷰 내용(지적 이슈 목록 포함)을 `local/context/{{taskId}}/code-review.md`에 저장한다.
반드시 해당 파일의 마지막 줄에 영문으로 `DONE`을 추가한다.
